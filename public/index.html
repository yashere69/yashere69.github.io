Tools for the AI agents Indian shops actually run.

WhatsApp support bots, voice agents, shopping assistants: nine small Python tools for testing them and keeping customers' data out of the model. Every one runs on this page, in your browser. Click a machine on the bench.

Python isn't loaded yet. It starts on your first run (about 10 MB, then cached).

    Send a message down the line

    Customers paste phone numbers, PANs and UPI ids into support chats. parda swaps them for tokens before the text reaches a model and puts them back in the reply. Models rarely copy tokens exactly, so pick how this one mangles them and compare parda's restore with a plain find-and-replace.

    The tools

    Each one is its own repository with tests, CI and a changelog, and each reports the number it does worst on. They also work together: nakli generates the chats chat2faq mines, chat2faq redacts with parda, and chatlens turns failed conversations into turncheck tests.

    nakli

    नकली, fake

    Seeded Indian D2C test data: customers, Shopify-style orders, Hinglish WhatsApp exports and IDs. Aadhaar, GSTIN and PAN values fail their check digits on purpose, so test data can never be a real person's number. Random digits pass Aadhaar's Verhoeff check one time in ten.

    Where it's weak: 26 customer phrasings and one store's catalog. It's repetitive by design; don't train on it.

    github.com/yashere69/nakli

    chat2faq

    Mines WhatsApp support exports into a redacted, source-linked FAQ for a support bot, and flags answers that need a lookup tool rather than a fixed reply. It reads Android and iOS exports in either date order. With parda installed, as here, it redacts with parda.

    Where it's weak: on 48 questions written independently of the sample, it answers 19 right at the default threshold. Character n-grams can't connect "paisa wapas" to "refund".

    github.com/yashere69/chat2faq

    parda

    पर्दा, a curtain

    Reversible redaction of Indian personal data around an LLM call: Aadhaar (Verhoeff), GSTIN (mod-36), PAN, UPI, phones in Devanagari digits or spoken aloud. It restores values only for tokens it issued, so a model can't make it fill in a value it never saw.

    Where it's weak: the round-trip numbers come from simulated rewrites, not a real model. On a held-out set, phone recall is 82% (landlines and pair-grouped numbers).

    github.com/yashere69/parda

    turncheck

    Regression tests for WhatsApp bots at the webhook level. It plays Meta's Cloud API: real signed webhooks over HTTP to your bot, then checks replies, tool calls, duplicate deliveries, the 24-hour window and how fast you acknowledge. A planted-bug study catches 9 of 9 bugs with no false failures.

    Where it's weak: payload shapes come from Meta's docs and an independent framework, never from captured production traffic. A browser can't start your bot, so only lint runs here.

    github.com/yashere69/turncheck

    chatlens

    A local, keyboard-first page for reading and labelling chatbot conversations during error analysis, then grouping the notes into failure modes. Nothing leaves 127.0.0.1. Its last command exports every failed conversation as a turncheck test, which is the loop the third button runs.

    Where it's weak: one reviewer at a time, with no adjudication view, and plenty of teams build their own labelling page in an afternoon.

    github.com/yashere69/chatlens

    mixslot

    Speech recognition garbles Hinglish numbers ("nau aath double saat"), and the voice agent then calls a tool with the wrong order id. mixslot measures how often that happens and normalises spoken numbers in three scripts before extraction, counting a refusal separately from a wrong value.

    Where it's weak: the synthetic benchmark below is optimistic. On real recogniser output (Whisper base, Hindi TTS) the normaliser raises correct values from 6.6% to 11.1% but doesn't lower wrong ones.

    github.com/yashere69/mixslot

    chunkbench

    Scores RAG chunking strategies on your own documents by token spans (recall, precision, IoU), with BM25 or embeddings. Compare at an equal word budget and the ranking changes, which is the confound it exists to show. Hindi is counted in graphemes.

    Where it's weak: the sample has 25 questions, so one Hindi question moves a Hindi score by 14 points, and no multilingual embedder has been measured.

    github.com/yashere69/chunkbench

    skill-preflight

    A check to run before installing an Agent Skill: spec conformance, how much context it costs, what its scripts actually do (read from their syntax tree) against what it declares, and instructions that pipe downloads into a shell or hide things from you. Its lockfile turns an update into a ranked diff.

    Where it's weak: the instruction rules are line-based and were tuned on the same demo attacks they're reported on. Use it next to a malware scanner, not instead of one.

    github.com/yashere69/skill-preflight

    shoplint

    Lints a Shopify product export for what AI shopping agents and product feeds can answer from structured fields, what is buried in prose and what is missing. It reads Shopify's current and legacy CSV templates; 20,800 products take under 4 seconds.

    Where it's weak: it hasn't been run on a real store's export yet. The sample is a fictional catalog with planted defects.

    github.com/yashere69/shoplint

    How this page works

    The consoles run the tools' own command-line entry points in Pyodide, CPython compiled to WebAssembly, inside a web worker. Each package is built in CI from its repository's release tag, and the page checks every file's sha256 against the build manifest before loading it.

    The site's tests run every console command in a real browser and in ordinary CPython and fail if the outputs differ, so what you see is what pip install and a terminal would show.

    Everything loads from this domain: no fonts, scripts or analytics from anywhere else. Add #debug to the address to see each request, the frame rate and run timings.

    The bench is drawn with three.js from plain boxes and cylinders. Bruno Simon's portfolio, where the site itself is the thing you play with, is the reason it exists.
